15차시 - 프롬프트와 확률 2 : 질문을 바꾸면 분포가 어떻게 달라질까?



1. 프롬프트 성능 실험 설계 실습



프롬프트 최적화
최적의 프롬프트는 고정된 것이 아니라, 주어진 상황과 태스크의 성격에 따라 결정됨.
실험 설계 - 실험 수행 - 평가 - 개선 사이클을 반복하며 주어진 태스크에 대한 성능을 높여야함.
-실험설계 : 변수 설정, 데이터셋 준비, 평가 기준 수립
-실험 수행 : LLM 추론, 결과 데이터 수집
-평가 : 정량 평가, 정성 평가, 결과 분석
-개선 : 개선 방향성 탐색, 프롬프트 최적화

프롬프트 성능 실험 설계
객관적인 최적화를 위해 실험을 설계한 다음, 변수를 정하고, 어떤 데이터로 테스트할지 준비하며, 어떤 기준으로 채점할지 명확한 계획을 수립해야함

데이터셋 준비
실험의 신뢰도를 높이기 위해 특정 유형에 편향되지 않은 테스트 데이터셋을 구축해야함. 실제 서비스 환경에서 발생할 수 있는 주요 시나리오들을 유형별로 분류하여 준비.

실험 변수 설정
통제된 환경에서의 비교를 위해서 생성 파라미터는 고정하고, 입력 프롬프트만 변경하여 성능의 변화를 관찰
고정 변수 : Temperature, Top-k, Top-p 
독립 변수 : 입력 프롬프트

정량평가 지표 :  텍스트 유사도
Bilingual Evaluation Understudy(BLEU) 는 모델이 생성한 문장이 정답 문장과 N-gram(연속된 n개의 단어) 단위로 얼마나 겹치는지를 측정.
단어의 등장(1-gram)과 순서(2~4gram)를 모두 고려하여 정밀도(Precision)를 산출함

정량평가 지표 :  LLM-as-Judge
LLM-as-Judge는 고성능 모델(GPT-5 등)을 심판관으로 활용하여 답변의 품질을 평가하는 방식임. 단순 단어 매칭을 넘어, 문맥적 적절성, 공감도, 논리성 등 인간과 유사한 기준으로 점수를 매길 수 있음.

정성평가 기준 수립
수치로 파악하기 힘든 '톤 앤 매너'나 '사실 관계 오류'는 사람이 직접 평가해야 함.
전체 데이터를 조사하는 것은 비효율적이므로, 각 유형별로 1~2개의 표본을 추출하여 분석하는 것이 효율적임
전체 데이터 -> 일부 데이터 -> 정성 평가(톤 앤 매너, 사실 관계, 규정 준수, 기타)



2. 실험 결과 분석 및 개선 실습



실험 수행 및 평가 결과 도출
테스트 데이터에 대해 LLM 추론을 수행하여 정량적 수치와 정성적 기준에 대한 평가 결과를 도출할 수 있음

결과 분석 및 개선 방향성 도출
각 지표의 결과를 종합하여 현재 프롬프트에서 모델이 어떤 강점과 약점을 가지는지 분석함. 진단 결과를 바탕으로, 약점을 보완하는 프롬프트 최적화 방안을 도출할 수 있음.
BLEU Score : 높을수록 매뉴얼 형식 일치
LLM-as-Judge : 높을수록 미리 정의한 평가 기준에 부합한 답을 생성하고 있음을 의미

프롬프트 성능 실험 보고서
실험환경, 사용모델, 데이터셋 구성, 버전 별 점수 명시.
