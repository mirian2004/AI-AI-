17차시 - AI 애플리케이션 구조 이해 : API 기반 모델 연동



1. 서버와 AI 모델의 대화 - API 통신 원리



챗봇의 겉모습 뒤에 숨겨진 구조
사용자는 채팅창을 보지만, 채팅창 뒤에는 수만 줄의 코드와 거대한 서버가 존재함.
채팅 UI(프론트엔드) - 백엔드 서버 - 데이터베이스 

API(Application Programming Interface)는 뭘까?
API는 프로그램 간의 약속을 의미.
서로 다른 프로그램이 대화하기 위해 만든 '표준화된 대화 규칙'이자 '통로'임

요청(Request)과 응답(Response)
API 통신의 기본 사이클로 클라이언트가 요청을 보내면(Request) 서버가 적절한 응답(Response)을 반환함.

우리가 사용할 주요 AI API
OpenAI와 Gemini와 같이 전세계적으로 주로 사용되는 API를 이용하여 특정 서비스에 AI를 '플러그인'처럼 꽂아 사용할 수 있음

ChatGPT 웹 vs OpenAI, 무엇이 다를까?
-ChatGPT(Web UI) : '사람'이 사용하며, 채팅창을 통해 질문하고 답변을 받음. 일회성 질문이나 창작에 유리
-OpenAI : '프로그램(코드)'이 사용하며, 개발자가 만든 앱이나 서비스가 서버와 통신. 대량의 데이터를 처리하거나 기존 서비스에 기능을 붙일 때 사용

API의 필요성
-사람이 일일이 입력하는 대신, 코드를 통해 수천 개의 리뷰 요약, 번역 등을 순식간에 처리 가능함
-DB와 연동하여 "내 일기장을 분석해주는 AI" 등 맞춤형 기능 개발 가능함
-채팅처럼 말하는게 아니라, JSON 같은 포맷으로 결과를 받아 앱 UI에 바로 적용 가능함.

AI 과금 체계 (토큰의 이해)
-토큰은 AI가 글을 읽고 쓰는 기본 단위
-내가 보낸 질문(Input)과 AI가 한 답변(Output)의 토큰 합계만큼 비용 지불
-질문을 효율적으로 하고, 불필요하게 긴 답변을 막아야(Max Tokens 설정 등) 비용을 아낄 수 있음 



2. 사용자 입력의 매핑 - API 파라미터 구성


 
텍스트를 데이터 상자에 담기
사용자의 텍스트 입력을 API에 전달하기 위해 'JSON'이라는 특수한 상자에 담아야함

API의 공식 언어, JSON 포맷
'키(Key)'와 '값(Value)'의 쌍으로 이루어져 데이터를 저장할 수 있는 유용한 형식임.
-"model"과 "messages" 파라미터에 사용할 AI 모델을 지정하고 시스템 프롬프트, 유저 질문을 입력함.

AI의 성격과 행동을 결정하는 파라미터
질문 외에도 온도(Temperature), 길이(Max Tokens) 등 파라미터를 설정하여 답변의 품질을 조절할 수 있음

온도(Temperature)
AI가 답변을 생성할 때 '가장 확률이 높은 단어'를 고를지 혹은 '의외의 단어'를 섞을지 결정함
-Low Temperature : 같은 답을 해야하는 고객센터 챗봇이나 코드 생성에 적합함.
-High Temperature : 창의적인 아이디어가 필요한 광고 카피 작성이나 소설 창작에 유리함

최대 토큰(Max Tokens)
답변의 길이를 제한하는 파라미터. 답변의 최대길이를 제한함으로써 API 비용 낭비를 방지하고 적절한 양의 정보를 생성할 수 있음

시스템 프롬프트(System Prompt)
대화 전반에 걸쳐 AI의 역할과 규칙을 정의하는 '개발자 전용' 지시문
-사용자는 해당 메시지를 볼 수 없지만, AI의 모든 답변은 시스템 프롬프트에 설정된 규칙 안에서 생성됨



3. 결과 가공 및 검증을 통한 AI 응답의 서비스화



AI 응답, 그대로 고객에게 보여줘도 될까?
ChatGPT, Gemini와 같은 웹 서비스에서는 AI의 답변만 표출되지만, API의 응답 그대로는 정제되지 않은 상태이며 그 안의 AI의 응답 또한 확인이 필요함.
-만약 AI가 반말을 하거나, 욕설을 하거나, API 응답을 가공하지 않고 제공하면 서비스 전체가 망가짐
-따라서 '서비스화(Productization)' 과정이 필수적임

데이터 추출(Parsing)
모델의 답변 전체에서 사용자에게 필요한 내용만 골라내는 과정
복잡한 JSON 데이터 구조에서 사용자가 실제로 읽어야 할 content를 선택적으로 추출함

텍스트 후처리(Post-processing)
가독성을 높이는 텍스트 정제 과정으로 AI 답변 중 불필요한 서론을 삭제하거나 텍스트를 웹페이지 레이아웃에 맞춰 변환함

서비스 가드레일 (1) 필터링
서비스 안전 기준을 설정하여 모델 자체 필터링 외에도 서비스 성격에 맞지 않는 키워드나 부적절한 내용을 서버에서 검사하는 과정

서비스 가드레일 (2) 할루시네이션 체크
거짓 정보가 섞여 있는지 확인하는 과정으로 AI가 지어낸 허위 사실이나 잘못된 링크가 존재하는지 확인하는 2차 검증을 수행함 

예외 상황 처리 (Error Handling)
서버 다운, 토큰 초과, 필터링 차단 등 AI 모델과의 통신이 어려운 경우 사용자에게 표시될 안내 메시지를 준비해야 함

서비스화 Before & After
AI 답변을 '제품'으로 만드는 단계로 추출, 가공, 검증 과정을 거쳐야 비로소 사용자가 만족하는 '서비스'가 완성됨.



4. API 연동형 서비스 로직 도식화



우리가 설계할 AI 서비스의 흐름
사용자의 입력이 어떤 경로를 거쳐 지능적인 답변으로 돌아오는지 전체 구조를 알아보고자 함.
-프론트엔드, 백엔드, AI 모델이 서로 협력하는 데이터 흐름을 알아봄

API 연동형 서비스의 표준 아키텍처
1단계 : 사용자 입력(Request)
2단계 : 백엔드 전처리 및 API 호출
3단계 : AI 연산 및 응답(Response)
4단계 : 백엔드 후처리 및 결과 출력
-각 단계가 끊기지 않고 유기적으로 연결되어야 빠른 응답이 가능

프론트엔드 역할 - 인터페이스 및 유효성
사용자의 입력을 백엔드로 전달하기 전 단계로 비어있는 값이 있는지 1차 검사
-AI가 답변을 생성하는 동안 사용자에게 로딩 애니메이션을 보여주어 심리적 대기시간을 줄일 수 있음
-사용자 친화적인 유저 인터페이스를 구성하여 사용에 불편함이 없도록 함

백엔드 전처리 - 주문서 작성
사용자의 질문에 서비스 운영자가 의도한 '페르소나(System Prompt)'를 결합함.
-설정된 파라미터(Temperature 등)와 API 키를 하나로 묶어 'JSON'이라는 규격화된 상자에 포장함

API 통신 - 주방으로의 주문 전달
완성된 JSON 데이터를 인터넷 통로(API)를 통해 OpenAI나 Google 서버로 전송.
-서버는 AI의 연산이 끝날 때까지 연결을 유지하며 답변 데이터를 기다림

백엔드 후처리 - 결과 검수와 포장 제거
AI의 답변을 서비스용 데이터로 정제
-AI가 보낸 복잡한 데이터에서 필요한 답변 텍스트만 추출함
-답변에 유해한 내용이나 서비스 규격에 맞지 않는 말투가 포함되어 있는지 최종 검수 및 교정

프론트엔드 출력 - 최종 사용자 경험
사용자에게 전달되는 지능적인 결과
-가공된 데이터를 받아 텍스트, 표, 이미지 등 사용자에게 직관적인 형식으로 화면에 표시함
-이와 같은 모든 과정이 매끄럽게 수해오디어야 사용자는 "AI가 똑똑하다"고 느낄 수 있음
