18차시 - AI 애플리케이션 데이터 파이프라인 설계(DB-AI 연동)



1. 데이터베이스와 SQL의 역할 이해



모델의 한계 - '우리' 데이터의 부재
외부 AI 모델(ChatGPT 등)은 인터넷에 공개된 정보는 응답할 수 있으나, 우리 조직만 보유한 고유 데이터(고객 정보, 재고 현황 등)는 접근할 수 없음.
-서비스의 경쟁력은 누구나 사용할 수 있는 공개 AI 모델이 아니라, 우리만 가진 고유 데이터에서 나옴

창작은 AI에게, 사실은 DB에게
AI(LLM)는 학습 데이터에 없는 정보에 대해 그럴듯한 거짓 정보를 생성하는 경향이 있음. 이를 '할루시네이션(Hallucination)'이라고 함. 
-이를 방지하기 위해 답변의 근거가 되는 '사실 정보'를 DB에서 가져와야함

정적 프롬프트 vs 데이터 결합 동적 프롬프트
AI는 사용자의 개인 정보를 알지 못하므로, 일반적 응답만 제공 가능함.
AI가 DB를 통해 개인 정보에 접근하면, 사용자 맞춤형 응답을 제공할 수 있음

데이터의 여정이 서비스의 품질
사용자의 질문이 다음 단계를 거쳐 처리되는 전체 과정을 '데이터 파이프라인'이라고 함
-데이터 파이프라인을 잘 구축할수록 신뢰할 수 있는 고품질 서비스를 제공할 수 있음
-일반적으로 DB는 백엔드 서버에서 추출/가공함

데이터베이스(DB)의 정의
대규모 데이터를 체계적으로 저장하고, 동시에 빠르게 처리 및 관리하는 시스템.
-대용량 데이터 저장 : 수백만 건 이상의 데이터 보관 가능
-빠른 조회 속도 :  필요한 데이터를 신속하게 검색
-안정성 : 데이터 무결성 보장 및 자동 백업
-동시성 : 여러 사용자가 동시에 접근 및 수정 가능

DB의 설계도 - 스키마(Schema)
데이터가 들어갈 칸의 이름(컬럼명)과 종류(숫자인지 문자인지)를 미리 정해둔 일종의 설계도

테이블(Table)
스키마에 정의된 구조에 따라 실제 데이터가 저장되는 곳
스키마의 정의에 맞춰서 행(Row)과 열(Column)로 구성된 데이터 집합

테이블의 구성 요소 - 행(Row)과 열(Column)
엑셀 시트처럼 가로줄(행)은 한 명의 정보나 한 건의 주문을, 세로줄(열)은 이름, 가격, 날짜 등 해당 데이터의 상세 항목을 의미함

관계형 데이터베이스(RDB)
여러 개의 독립적인 테이블들로 이루어진 데이터베이스.
각 테이블은 서로 '키(Key)'를 통해 연결되어 있음
-기본키(PK) : 각 행을 유일하게 식별하는 고유값
-외래키(FK) : 다른 테이블의 PK를 참조하여 연결하는 값

SQL - DB와 대화하는 언어
SQL(Structured Query Language)은 관계형 데이터베이스에 데이터를 조회, 삽입, 수정, 삭제하기 위한 표준화된 명령어 언어



2. 기초 SQL 쿼리를 활용한 데이터 조회



SQL 기초 문법 (1) - SELECT와 FROM
SELECT와 FROM은 SQL 쿼리의 기본 요소로, 어떤 데이터를 어디서 가져올지를 정의함.
-SELECT : 결과에 포함할 컬럼(또는 계산된 표현식)을 지정해 반환 형태를 정의함 
-FROM : 데이터를 가져올 테이블을 지정하여 검색 대상 범위를 정함 

SQL 기초 문법 (2) - WHERE
엑셀의 '필터' 기능과 같음. 수많은 데이터 중 조건에 맞는 데이터만 정확히 골라냄
-WHERE : 특정 조건을 만족하는 행만 필터링해서 조회/수정/삭제하도록 지정함



3. DB 데이터의 AI 모델 결합 원리



DB 데이터를 어떻게 AI에게 전달할까
1. 사용자의 액션(버튼/메뉴 등)에 따라 미리 작성된 SQL 쿼리를 실행하고 결과를 전달함
2. 사용자의 자연어 질문을 SQL 쿼리로 자동 변환하여 실행하고, 결과를 전달함

지정된 SQL 쿼리 실행 - 상품 추천 시스템 예시
사용자가 특정 상품을 구매했을 떄, 주문 내역에 따라 추가로 구매할만한 상품을 추천해주는 시스템
1) 사용자(고객)가 특정 상품을 구매함
2) 서버에서 지정된 SQL(SELECT 상품명 FROM 주문테이블 WHERE {고객ID}) 쿼리를 통해 주문 내역을 받아옴
3) 조회된 주문 내역을 AI에 전달하여 분석 후, 맞춤형 추천 상품을 제안함

Text-to-SQL - 자연어를 SQL 쿼리로 변환하기
사용자의 질문을 입력으로 받아, 질문 의도에 맞는 SQL 쿼리를 자동 생성하는 기법
-개발자가 SQL 쿼리를 매번 직접 작성하지 않아도, 사용자 질문을 SQL 쿼리로 변환하여 DB 조회가 가능함

Text-to-SQL - AI에게 스키마(Schema) 전달하기
AI가 자연어 질문을 SQL로 정확하게 변환하려면, 먼저 우리 데이터베이스의 구조(스키마)를 이해해야 함
-사용자의 자연어 질문과 스키마 결합 - 사용자의 질문과 DB 스키마 정보를 함께 AI에 입력함



4. 동적 프롬프트 구성 : DB 조회 결과의 자동 주입



SQL 결과 데이터 포장 - JSON
DB에서 추출된 행/열 데이터를 AI가 이해하기 쉬운 {"이름": "철수", "구매": "운동화"} 형태의 JSON 포맷으로 변환해야함

동적 프롬프트 구성 - 데이터 주입
"사용자의 최근 구매 기록은 {데이터}야. 이를 보고 취향을 분석해줘." 처럼 중괄호{} 안에 실제 데이터를 DB에서 조회하고 결과를 주입해 질문을 완성.
DB 데이터가 프롬프트에 주입되므로, 일반적인 응답보다 더 개인화된 응답을 AI에게서 얻을 수 있음

정리 - 정보의 요약과 가공
-DB에서 조회한 원본 데이터는 그대로는 양이 많아 해석이 어려울 수 있음
-AI를 활용하면 조회 결과를 요약/가공하여 핵심 메시지 형태로 변환할 수 있음
-요약된 결과는 대시보드/리포트/알림 문구 등으로 활용 가능함
 
정리 - 사실 기반의 답변 구성
AI는 DB에서 가져온 실제 숫자와 정보를 바탕으로 답변하므로, 할루시네이션을 완화할 수 있으 신뢰할 수 있는 정보를 제공할 수 있음



5. AI 서비스 아키텍쳐 분석



전체 데이터 파이프라인
DB-AI 연동 AI 서비스의 아키텍처를 분석함
사용자 질문 -> SQL 생성/실행 -> 데이터 검색 -> 인사이트 생성 -> AI 분석/출력

SQL 쿼리 생성/실행
사용자의 질문에 따라 Text-to-SQL을 통해 SQL을 생성해 실행하거나, 미리 입력한 SQL 쿼리를 실행하는 단계

데이터 검색(Data Retrieval)
실제 데이터를 DB에서 꺼내오는 단계로, 생성된 SQL을 실제 데이터베이스에 실행하여 필요한 데이터를 확보 

인사이트 생성(Insight Generation)
데이터를 정보로 가공하는 단계로, 추출된 데이터를 다시 프롬프트에 입력해 AI에게 전달하고, AI가 이를 분석해 사용자가 이해하기 쉬운 결과물로 최종 변환함



실습 : DB 연동 API 호출
