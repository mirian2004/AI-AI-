20차시 - [종합 프로젝트] 사내 데이터 분석 어시스턴트 : DB-AI 연동 파이프라인 구축



1. 문제 상황 정의



문제 상황 정의
법인카드를 부정하게 사용하는 사람을 찾아야함. 하지만 카드 결제 내역이 너무 많아서 재무팀이 일일이 확인하는 것이 불가능한 상황임

프로젝트 목표 정의
프로젝트 목표 : 재무팀 직원이 수 많은 법인카드 거래 데이터를 쉽고 정확하게 분석할 수 있도록 지원하는 "사내 거래 데이터 분석 어시스턴트"를 구축


데이터 분석
법인 카드 결제내역 데이터는 '법인카드 거래내역 DB'에 3개의 테이블로 구분되어 저장됨.
- Employees(직원 아이디, 이름, 부서, 직급)
- Transactions(거래 아이디, 직원 아이디, 가게 아이디, 결제 날짜, 결제 시간, 금액, 휴일 여부)
- Merchants(가게 아이디, 가게 이름, 업종, 지역)
주어진 데이터에 대해, SQL을 활용하여 정보 조회가 가능함

프로젝트 목료 구체화
문제 상황 분석 및 데이터 분석
- 배경 : 법인 카드 부정 사용자 색출을 위해 카드 결제 내역 분석이 필요하지만, 일일이 확인할 수 없음
- 데이터 접근성 : 사내 데이터는 테이블로 구성되어 있어, SQL Query를 통해 정보 조회가 가능함
- 현실적 제약 : 재무팀 담당자는 SQL에 대한 전문 지식이 부족하여, DB에 직접 접근하여 데이터를 분석하는 데 어려움이 있음
프로젝트 목표 구체화
재무팀 직원이 자연어로 질문하면, AI가 이를 SQL Query로 번역하여 데이터를 추출함으로써 데이터 분석을 도와주는 DB 어시스턴트 구축



2. 파이프라인 구축 실습



파이프라인 구축
자연어 입력을 받아 DB를 참고하여 답변을 생성하는 DB 어시스턴트 구축이 최종 목표임

파이프라인 구축 - Text-to-SQL
먼저, 자연어가 주어지면 DB에서 정보를 뽑을 수 있는 SQL로 번역하는 과정이 필요함. 
자연어를 SQL로 변환하는 작업을 Text-to-SQL 이라고 함
LLM이 정확한 SQL을 생성하기 위해서는 충분한 DB 정보(DB 스키마)를 입력 해주어야 함

파이프라인 구축 - SQL 실행
LLM을 활용해 SQL로 번역이 완료되면, 해당 SQL을 DB에 실행하여 필요한 데이터를 추출해야 함

파이프라인 구축 - 답변 생성
SQL 실행 결과는 숫자 데이터로, 사람이 이해하기에 적절한 형태가 아님. 
DB 어시스턴트는 추출된 데이터를 바탕으로 문맥에 맞게 자연어 형태의 답변을 제공해야 함

전체 파이프라인
유저 -> Text-to-SQL -> SQL 실행 -> 답변 생성 



3. 실험결과 분석 및 한계 정리



파이프라인 평가 - 테스트 데이터 준비
DB 어시스턴트 평가를 위해 사용자 질문과 SQL 정답 쌍으로 구성된 테스트 데이터셋이 필요함

파이프라인 평가 - 평가 지표 설정
DB 어시스터트의 평가는 두가지 평가 지표를 통해 이루어짐
Execution Accurancy
- SQL이 올바르게 생성되었는지 평가
- LLM이 생성한 SQL을 실행했을 때의 결과와 정답 SQL 실행 결과가 동일한지 판단
Response Accurancy
- 최종 응답이 적절한지 평가
- LLM-as-Judge(LLM 심판관)을 통해 응답의 정확성, 무결성, 적절성을 평가

파이프라인 평가 - 평가 수행

파이프라인 평가 - 결과 분석
결과 리포트 분석

실무 적용 : 법인 카드 부정 사용자 찾기

한계점 파악
구축된 어시스턴트를 실무에 활용하는 과정에서 발생한 불편한 점들을 분석함으로써, 현재 파이프라인의 한계점을 파악할 수 있음

개선 방향성 탐색
최종 답변을 생성할 때 SQL 정보를 제공하고 어떤 과정을 거쳐 답변을 생성했는지 설명하도록 지시한다면, 사용자는 어시스턴트의 답변 근거를 확인할 수 있음
